## Part 1: Assessment Questions & Answers

### Learning Outcome 1: Define EDP Components

#### 1. What is an event? Give two examples.
- **Definition:** An event is an asynchronous message, signal, or data object emitted when a notable change of state occurs within a system or via user interaction.
- **Examples:**
  1. `ActionEvent` fired when a user clicks a button in a GUI.
  2. `KeyEvent` generated when a user presses a physical key on the keyboard.

#### 2. What is an event source? Give two examples.
- **Definition:** An event source is the hardware device, UI component, or system service that detects an action and instantiates/emits an event.
- **Examples:**
  1. A `JButton` or `JTextField` component in Java Swing.
  2. A physical sensor, such as an infrared PIR motion detector or capacitive touchscreen.

#### 3. What is an event listener? Give two examples.
- **Definition:** An event listener is an interface or object registered with an event source designed to wait for, capture, and observe notifications of specific event types.
- **Examples:**
  1. `java.awt.event.ActionListener` in Swing.
  2. `java.awt.event.MouseMotionListener` for tracking cursor coordinates.

#### 4. What is an event handler? Give two examples.
- **Definition:** An event handler is the concrete method or executable callback function invoked by the listener to carry out specific business logic in response to the event.
- **Examples:**
  1. The `actionPerformed(ActionEvent e)` method executing a calculation or database query.
  2. A lambda function `e -> display.setText("0")` that resets calculator state.

### Learning Outcome 2: Compare Paradigms

#### 6. How does procedural programming differ from event-driven programming?
- In **procedural programming**, program execution follows a rigid, predetermined top-to-bottom sequence directed by the code itself. The program dictates when and what inputs are collected, blocking until the user responds.
- In **event-driven programming**, control flow is inverted ("Inversion of Control"). The program stays in an idle event loop waiting for external events (clicks, network packets, timer ticks). The user or external environment dictates the sequence and timing of code execution.

#### 7. What is the main advantage of event-driven programming for GUIs?
- It provides a **responsive, non-linear, and intuitive user experience**. Users can interact with any visible component at any time, in any arbitrary sequence, cancel ongoing actions, make corrections, and receive immediate graphical feedback without freezing the interface.

#### 8. In which scenario would you choose procedural programming over event-driven?
- Procedural programming is preferred for **linear batch jobs, numerical computations, ETL data pipelines, compile scripts, and simple CLI setup tools** where operations must execute in a strictly defined step-by-step order from start to finish without interactive user pauses or asynchronous triggers.

### Learning Outcome 3: Event Loop and Queue

#### 9. What is the event loop? What does it do?
- The event loop is a continuous background thread loop that repeatedly checks the event queue, retrieves pending event objects in FIFO order, resolves their registered listeners, and executes their associated callback handler routines.

#### 10. What is the event queue? How does it work?
- The event queue is a First-In, First-Out (FIFO) buffer that stores events generated by the OS, hardware interrupts, timers, or user inputs until the event loop is ready to process them sequentially.

#### 11. Why should the event loop never be blocked?
- Because the event loop is typically single-threaded and handles both event handling and graphical rendering. If a handler performs a slow operation (e.g., synchronous sleep, large file I/O, network requests), the loop halts; the GUI stops repainting, becomes frozen, ignores all user clicks, and triggers OS "Not Responding" errors.

#### 12. What is the EDT in Java Swing?
- The **EDT (Event Dispatch Thread)** is the dedicated background thread in Java Swing responsible for running the Swing event loop: polling AWT events from the `EventQueue`, invoking listener callbacks, and repainting Swing components. All component mutations must strictly execute on the EDT to ensure thread safety.

### Learning Outcome 4: Real-World Examples

#### 13. List five real-world event-driven systems.
1. **Automated Teller Machines (ATMs)**
2. **Elevator Dispatch and Safety Systems**
3. **Smart Thermostats (e.g., Nest)**
4. **Modern Web Applications & Browsers**
5. **Modern Automotive Engine Control Units (ECUs) / Dashboards**

#### 14. For one system, identify all four EDP components.
- **System: Automated Teller Machine (ATM)**
  - **Event Source:** Physical Card Slot Sensor
  - **Event:** `CardInsertedEvent` (carrying magnetic/chip payload)
  - **Listener:** `CardReaderListener` daemon
  - **Handler:** `startCustomerSession()` (validates card chip, prompts for PIN on screen, starts inactivity timer)

#### 15. Why are most modern applications event-driven?
- Modern applications are inherently interactive, distributed, and concurrent. Users interact via touchscreens, mouse clicks, and voice; devices receive unpredictable notifications, hardware interrupts, webhooks, and sensor readings simultaneously. Event-driven programming matches the natural reality of real-world interactions where systems must remain reactive, non-blocking, and asynchronous.
